# 🚀 [프로젝트 보고서] 2D 아파트 도면 객체 검출 및 디지털 구조화 파이프라인

## 1. 프로젝트 개요
- **목표**: 2D 건축 도면 이미지를 딥러닝(YOLOv8)으로 분석하여 가구 및 구조물, 텍스트(OCR)를 추출하고 디지털 구조화(3D 변환의 기반)하는 베이스라인 구축.
- **주요 과제**: 방대한 고해상도 도면 데이터의 전처리 병목 해결, 클래스 불균형 및 라벨 매핑 문제 극복, 하드웨어(L40S) 한계점 돌파.

---

## 2. 데이터 전처리 및 마스터 데이터셋 구축 (가장 큰 시행착오)

### 🚨 시행착오 1: 원천 데이터의 불규칙한 파일 매핑
초기에는 단순히 `TS_OBJ_1.zip` (이미지)과 `TL_OBJ_1.zip` (라벨) 폴더의 인덱스가 1:1로 일치할 것이라 가정하고 1,473장을 무지성 추출했습니다. 하지만 실제 AI 허브 데이터는 폴더 번호와 관계없이 파일이 흩어져 있어, 정답지(JSON)와 이미지(PNG)의 쌍이 맞지 않는 치명적인 데이터 오염이 발생했습니다.

### 💡 해결방안: 전수 조사 기반 해시 매칭 (Hash & Size Matching)
단순 파일명 매칭을 폐기하고, **모든 ZIP 파일을 샅샅이 뒤져 파일 크기(Size)와 CRC32 해시값을 교차 검증**하는 강력한 파이프라인(`build_master_dataset.py`)을 전면 재개발했습니다.
- **결과**: 숨겨져 있던 퍼펙트 매칭 페어 **총 2,107장**을 완벽하게 발굴해냈습니다.

### 🛠 최적화: 1500장 정예 추출 및 WebP 50% 리사이징
특정 아파트 단지의 도면 스타일로 모델이 편향되는 것을 막기 위해 2,107장을 완벽하게 랜덤 셔플(Shuffle)한 후, 딱 **1,500장**을 추출했습니다.
- **용량 폭발(OOM) 방지**: 4963x3509 해상도의 무거운 PNG를 50%로 축소하고 고효율 `.webp` 포맷으로 변환했습니다. YOLOv8의 입력 해상도(640x640)를 고려할 때 정확도 손실 없이 디스크 I/O 속도만 비약적으로 끌어올렸습니다. (총 용량 약 206MB로 압축 성공)
- **8:1:1 황금 분할**: Data Leakage 방지를 위해 철저하게 `Train(1200) : Val(150) : Test(150)` 폴더로 분리하여 YOLO 포맷팅을 완료했습니다.

## 3. 7클래스 앙상블 & OCR 전이학습 아키텍처 확정

### 🚨 시행착오 2: 텍스트(OCR)와 가구의 특징 충돌
초기에는 5종의 가구와 2종의 구조물(문, 창호)에 OCR 텍스트 박스까지 합쳐 8개 클래스를 한 번에 학습시키려 했습니다. 하지만 텍스트 박스의 좁고 긴 비율(Aspect Ratio)이 가구나 구조물의 형태적 특징(Feature)과 너무 달라 모델이 혼란을 겪는 현상이 발견되었습니다.

### 💡 해결방안: 2-Stage 도메인 전이학습 (Transfer Learning)
어차피 우리는 텍스트의 "내용"을 읽는 것보다 텍스트의 "위치"를 찾는 Detection이 중요합니다. 이를 앙상블 구조로 분리했습니다.
1. **7클래스 마스터 모델 (Phase 2)**: 변기, 세면대, 싱크대, 욕조, 가스레인지, 출입문, 창호 7종을 완벽히 잡는 메인 모델(`yolov8m.pt`)을 150 에폭 동안 훈련시킵니다.
2. **OCR 전이학습 모델 (Phase 3)**: 마스터 모델이 "도면 특유의 흑백 선과 구도"를 이미 완벽하게 이해한 황금 가중치(`best.pt`)를 넘겨받습니다. 백지상태가 아닌 이 가중치에서 OCR 텍스트(단일 클래스)만 전이학습(Fine-tuning)시킴으로써, 불과 50에폭 만에 압도적인 속도와 정확도로 텍스트를 탐지해 냅니다.

## 4. 하드웨어 스펙 100% 활용 (L40S PRO 모드)

### 🚨 시행착오 3: 하이엔드 GPU 점유율 60% 병목 현상
NVIDIA L40S(VRAM 48GB) 및 RAM 120GB라는 막강한 워크스테이션을 투입했음에도, 초기 코드의 보수적인 셋업(`batch=16`, `workers=8`, `yolov8n.pt`)으로 인해 GPU 사용률이 60%를 겉도는 심각한 병목이 발생했습니다. 

### 💡 해결방안: Hardware-Aware Dual Profile 도입
메인 노트북 최상단에 **모드 스위치(PRO vs CONSUMER)**를 도입하여, 코드를 뜯어고칠 필요 없이 하드웨어 스펙에 맞게 즉시 파라미터가 튜닝되도록 리팩토링했습니다.
- **PRO 모드 적용**: 가벼운 Nano 모델을 버리고 성능이 압도적인 **Medium 모델(`yolov8m.pt`)**을 채택. 
- **Anti-OOM 안전장치**: VRAM 50GB 한도 내에서 피크치가 튀어 터지는 것을 완벽히 방어하기 위해 `Batch Size = 32`, `Workers = 8`의 **안전제일 고속 세팅**을 적용.
- **결과**: 점유율이 90~100%를 아름답게 찌르며 (첨부된 L40S Studio 차트 증명), 무거운 Medium 모델을 150 Epoch나 돌리는데도 1 에폭당 단 12초(총 30분)밖에 걸리지 않는 극한의 효율을 달성했습니다.

## 5. 핵심 성과 (Data Scaling Ablation)
데이터 무지성 투입이 능사가 아님을 수학적으로 증명하기 위해, 학습 데이터를 `[300, 600, 900, 1200]`장으로 점진적으로 늘려가며 성능을 측정했습니다.
- **결과**: 데이터가 증가함에 따라 mAP@50 성능이 0.253 ➔ 0.425 ➔ 0.510 ➔ **0.570** 으로 아름다운 우상향 수렴 곡선을 그리는 것을 증명해냈습니다. 
- 1200장(Train 최대치)에서 과적합 방지(Early Stopping)와 결합하여 최상의 베이스라인 모델을 확립했습니다.
